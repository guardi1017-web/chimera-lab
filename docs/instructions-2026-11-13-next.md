## 1. 지금 어디까지 왔나
- 사용자가 폰으로 직접 해 보며 여기까지 고쳤다. **재미 판정은 사용자 폰이 한다.**
- 통한 것(사용자 확인):
  - 첫 30초의 흐름 "잡몹 먹여 불리기 → 돌격조 → 자폭 → 심장 주워 재연성"이 한 손으로 이어진다.
  - 두 번 톡톡(자폭)은 잘 된다. 연결선은 읽힌다.
  - 초소를 부수고 대장을 잡는 것이 목적으로 느껴진다. 목적이 생기자 서너 판을 이어서 했다.
- 사용자 결정(바꾸지 마라):
  - 배경은 서울 같은 현대 도시. 3D 쿼터뷰로 옮긴다.
  - 키메라는 다음 구역으로 **데려가지 않는다.** 구역마다 맹수 하나로 처음부터 키운다. 쓰러지면 그 구역을 다시 한다.
  - 느려짐(슬로 모션)은 뺐다. 적이 나오는 양은 줄인 채로 둔다.
  - 폭탄은 **네크로맨서에게 가장 가까운 적**에게 뛰어든다(초소·돌격조·대장은 1.5만큼 더 멀어도 먼저). 화면에 조준 표시가 뜬다.
  - 폭탄은 익혀야 한다. 불안정도 80% 이상이어야 제대로 터지고, 덜 익은 채 터뜨리면 약하고 유전자를 잃는다.
  - 구역이 오르면 적이 25%씩 세져 언젠가 맹수 하나로는 못 시작한다. 이것은 **구역을 차지할 때 얻는 재화로 초기 소환수를 강화**하는 식으로 푼다(아직 안 만들었다).
- 마지막으로 받은 말: "어렵다, 조금만 낮추자" → 낮췄다(초소 피해 3, 대장 체력 600, 돌격조 피해 25·12). 그 뒤 사정거리 표시와 조준 표시를 넣었다. **이 상태의 난이도는 아직 사용자 확인을 받지 못했다.**

## 2. 일하는 방식 (Warhole을 접으며 배운 것. 꼭 지켜라)
1. **사용자가 말한 것만 만든다.** 이 프로젝트에서 Claude가 사용자의 말을 제 생각으로 바꿔 만든 일이 여러 번 있었다(합성 → 부위 붙이기, "데려갈 필요 있나" → 모두 데려가기, 묻지 않은 난이도 상향). 말이 두 가지로 읽히면 만들기 전에 물어라.
2. **재미를 봇이나 AI 테스터로 판정하지 않는다.** 봇은 예외·회귀·수치 비교에만 쓴다. 봇 승률과 손의 난이도는 크게 다르다(봇 6/40인 판을 사용자는 첫 판에 깼다).
3. **한 번에 하나씩 바꾸고 폰 확인을 받는다.** 여러 개를 한꺼번에 바꾸면 무엇 때문에 달라졌는지 모른다.
4. **질 수 있어야 한다.** 쉬워지면 아무것도 의미가 없어진다. 다만 난이도는 사용자가 올리라고 할 때만 올린다.
5. **좋았던 순간을 쉽고 자주 일어나게 만들지 않는다.** 사용자가 "폭발 빈도를 조금 낮추자"고 했다.
6. **규칙을 쌓기 전에 구멍을 본다.** 사용자가 "어느 순간 자폭만 시키고 있다"를 찾아냈다. `test.cjs`의 '마구 터뜨림' 봇이 이 구멍을 지킨다. **이 봇의 구역 정복이 0에서 벗어나면 고쳐라.**
7. 실제 화면을 볼 수 있으면 직접 열어 확인해라(이 PC에서는 한 번도 화면을 보지 못하고 만들었다). 확인하지 못한 것은 못 했다고 적어라.

## 3. 다음에 만들 것 (이 순서로. 단계마다 push하고 멈춰 사용자 확인을 받는다)

### 3.1 먼저: 지금 판의 난이도 확인
- 만들 것은 없다. 사용자에게 지금 판(위 주소)을 해 보고 어디서 쓰러지는지(초소에 다가가다 / 대장 / 돌격조) 물어라. 답에 따라 그 부분의 `CFG` 값만 고친다.

### 3.2 3D 쿼터뷰 (현대 도시의 밤)
목표는 **규칙을 그대로 두고 그리는 쪽만 3D로 바꾸는 것**이다. `src/sim.js`는 건드리지 않는다.
- 브라우저용 3D(Three.js)로 만든다. Unity로 옮기지 마라. 지금처럼 push 한 번으로 폰에서 확인하는 속도를 지킨다.
- **2D 판은 그대로 두고 `3d.html`에 따로 만든다.** 사용자가 폰에서 괜찮다고 하면 그때 `index.html`을 바꾼다.
- 권하는 구조:
  - WebGL 캔버스(`#game3d`) 위에 지금의 2D 캔버스(`#game`)를 투명하게 겹친다. 위쪽 표시(초소 칸, 체력, 키메라 칸), 등급 숫자, 가장자리 화살표, 조이스틱, 입력은 지금 코드를 그대로 쓴다.
  - `src/render.js`의 그리기에서 "판 좌표로 그리는 부분"만 3D로 대체한다. 화면 좌표가 필요한 곳(`sx`, `sy`, 톡 누른 키메라 찾기)은 3D 카메라의 투영으로 바꾼다.
  - 카메라는 직교 투영, 45도 돌린 쿼터뷰, 네크로맨서를 따라간다. **조이스틱 방향을 카메라에 맞춰 돌려야 한다**(화면 위쪽으로 끌면 화면 위쪽으로 가야 한다).
  - 키 큰 건물은 판의 **먼 쪽 두 변에만** 세운다. 가까운 쪽에 세우면 판을 가린다. 판 안에는 길을 막는 건물을 두지 않는다(규칙에 충돌이 없다).
- 그릴 것:
  - 바닥: 밤의 아스팔트, 차선과 횡단보도. 둘레에 불 켜진 창의 건물, 네온 간판, 가로등.
  - 키메라: 지금의 "유전자 개수만큼 붙는다"를 기본 도형으로 옮긴다. 주 유전자가 몸(맹수 뿔 모양 / 갑주 상자 / 사수 공), 섞인 유전자가 가시·장갑판·눈알. 불안정도에 따라 붉어지고 떤다. 사용자는 "섞이면 외형이 실제로 바뀌는 것"을 기대한다.
  - 적: 군견(맹수), 방패 기동대(갑주), 소총수(사수), 돌격조, 진압 대장. 지금은 색과 모양으로만 구별한다.
  - 초소(사정거리 원 포함), 혼(불량·신선·순혈), 심장(덜 익은 것은 흐리게), 연결선, 조준 표시, 돌진 예고 길, 폭발.
- 사용자가 한 말: "화려하진 못해도 깔끔하게 보여야 한다." 요소를 늘리지 말고 정돈해라. 색은 `src/page.html`의 토큰을 쓴다.
- 폰 성능을 먼저 본다. 그림자와 후처리는 쓰지 마라. 적 40마리와 효과가 떠도 끊기지 않아야 한다.
- 확인: `3d.html`을 브라우저로 직접 열어 화면을 본다(가능하면 폰 크기로). 조이스틱 방향, 톡 눌러 찍기, 두 번 톡톡, 위쪽 칸 누르기가 2D와 같게 되는지 본다.

### 3.3 구역 사이의 재화와 초기 소환수 강화 (사용자가 방향만 정했다)
- **만들기 전에 사용자에게 물어 정해라**: 재화를 무엇으로 얻는지(구역 정복, 돌격조 처치, 남은 시간 등), 무엇을 강화하는지(시작 소환수의 유전자 수, 종류 선택, 시작 마릿수 등), 쓰러지면 재화와 강화가 남는지.
- 저장은 `localStorage`에 버전을 붙여 둔다(지금은 최고 구역만 `chimera-lab-best-v1`에 있다).
- 강화가 들어가면 구역 배율(+25%)과 함께 다시 맞춰야 한다. 봇으로 수치를 보고, 판정은 폰으로 받는다.

### 3.4 그 뒤 (사용자가 꺼내면)
- 소리: 사용자 폰이 진동 모드라 한 번도 확인받지 못했다.
- 몬스터 그림: 지금은 도형이다. 2D 그림이 필요해지면 그때 정한다.

## 4. 정리할 것 (작은 일. 3.2를 하기 전에 해도 된다)
- 쓰지 않는 코드: `sim.js`의 `squadOf`·`aceOf`·`opts.squad`·`opts.ace`(키메라를 데려가던 기능), `slowing`·`slowLeft`·`slowScale`·`slowMax`·`slowRecharge`(느려짐), `render.js`의 느려짐 테두리. 지우고 관련 테스트를 맞춰라.
- 이름: 코드와 테스트 문구에 "돌격병"과 "돌격조"가 섞여 있다. "돌격조"로 맞춰라.
- `artifact.html`은 더 쓰지 않는다. `build.cjs`에서 빼도 된다.
- 최근 변경(목적, 구역, 자폭 구멍 수정, 조준 변경)은 Codex 검증을 받지 않았다. `/duo`로 한 번 돌려도 좋다.

## 5. 명령과 규칙
```bash
node build.cjs   # src → index.html (직접 고치지 말 것)
node test.cjs    # 규칙 테스트 + 봇 40판 × 4가지
node smoke.cjs   # 가짜 화면으로 화면 코드를 끝까지 돌려 본다
```
- 규칙은 `src/sim.js`에만 둔다(화면·DOM 없음, 같은 시드 같은 결과). 밸런스 값은 `CFG`에 모은다. 규칙을 바꾸면 `test.cjs`에 테스트를 넣는다.
- 판 안에 버튼을 늘리지 않는다. 판 중에 읽을 글을 늘리지 않는다. 한 손 조작.
- 커밋 메시지는 한국어, `feat(sim):` 같은 머리말. 기능 단위로 나눠 커밋하고 push한다.
- **이 저장소는 공개다.** 비밀값을 넣지 마라. 커밋 작성자 메일은 이 저장소에 `guardi1017-web@users.noreply.github.com`으로 설정해 쓴다(`git config user.email`).
- 줄 끝은 LF다(`.gitattributes`).
- 사용자에게 보고할 때: 무엇을 바꿨는지, 확인한 것과 못 한 것, 폰에서 볼 것을 적는다. 봇 수치는 참고로만 적는다.
