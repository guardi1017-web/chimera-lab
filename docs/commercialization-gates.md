## 0. 판정 원칙

1. **재미·화면·실제 렌더링·소리는 사장의 실제 폰 플레이로 판정한다.** 지시서 2-2: "재미를 봇이나 AI 테스터로 판정하지 않는다." README: "재미 판정은 봇이 아니라 폰에서 직접 해 본 느낌으로 한다."
2. **자동 검증이 보는 것과 못 보는 것을 나눈다.**
   - `node test.cjs`: 규칙 테스트와 봇 판. 예외·회귀·수치 비교만 본다. 봇 승률은 손의 난이도와 다르다(지시서 2-2: 봇 6/40인 판을 사용자는 첫 판에 깼다).
   - `node smoke.cjs`: 가짜 DOM으로 `2d.html`의 화면 코드를 끝까지 돌려 예외만 본다. **실제 브라우저의 WebGL/Three.js 렌더링(`index.html`의 3D 판), 화면이 어떻게 보이는지, 소리, 진동, 아트·에셋 품질은 보지 못한다.**
   - 문서(권리 기록, 이 문서 자체)가 맞는지는 자동 검증이 판단하지 않는다. 사장(운영자)이 확인한다.
3. **한 번에 하나씩.** 지시서 2-3에 따라 관문 판정을 위해 무엇을 고칠 때도 한 번에 하나만 바꾸고 폰 확인을 받는다.
4. **비용이 드는 일은 먼저 묻는다.** 표에서 `ask_first`로 표시한 항목은 돈이 나가거나 외부에 등록되는 일이므로, 실행 전에 사장 승인을 받는다.

## 2. 관문별 상세

### 관문 1. 현재 난이도 사장 폰 확인
- **지금 기록:** 지시서 1: 마지막으로 받은 말 "어렵다, 조금만 낮추자" 뒤 초소 피해 3, 대장 체력 600, 돌격조 피해 25·12로 낮추고 사정거리·조준 표시를 넣었다. "이 상태의 난이도는 아직 사용자 확인을 받지 못했다." 지시서 3.1은 만들 것 없이 사장에게 묻는 단계다.
- 명세 6장에는 그 뒤에도 폰 확인 기록(2026-11-14 "아직 어렵다", "4구역은 못 깨겠다" 등)이 있지만, **지금 배포판 전체를 기준으로 "이 난이도로 됐다"는 확정 기록은 없다.**
- **판정 방법:** 사장이 https://guardi1017-web.github.io/chimera-lab/ 을 폰으로 해 보고 어디서 쓰러지는지 답한다. 답에 따라 그 부분의 `CFG` 값만 고치고 다시 확인한다.
- **자동 검증의 역할:** `test.cjs`의 '마구 터뜨림' 봇 구역 정복이 0인지만 본다(지시서 2-6). 봇 승률은 통과 근거로 쓰지 않는다.
- **지킬 것:** 질 수 있어야 한다. 난이도는 사장이 올리라고 할 때만 올린다(지시서 2-4).

### 관문 2. 3D 판의 스마트폰 수용성
- **지금 기록:** 명세 6장(2026-11-14): "3D 쿼터뷰가 훨씬 잘 보이고 부드럽다. 첫 화면을 3D로 바꿨다(2D는 `2d.html`)." 그 뒤 3D 모델(`assets/*.glb`), 폭발 연출, 평타 몸짓 등이 더해졌다.
- **넘었다고 볼 조건(지시서 3.2의 확인 항목에서 가져옴):**
  - 적이 많고 효과가 떠도 끊기지 않는다(지시서: 적 40마리, 그림자·후처리 쓰지 않음).
  - 조이스틱 방향이 화면 방향과 맞고, 톡 찍기·두 번 톡톡·위쪽 칸 누르기가 2D와 같게 된다.
  - "화려하진 못해도 깔끔하게 보여야 한다"를 사장이 만족한다고 판정한다.
- **판정 방법:** 사장 폰 플레이. **WebGL/Three.js의 실제 렌더링은 실제 브라우저에서만 확인된다.** `smoke.cjs`는 가짜 DOM으로 `2d.html`만 돌리므로 이 관문의 근거가 되지 못한다.
- **확인할 폰:** 사장 폰 외 다른 기종에서도 볼지는 사장이 정한다(아래 체크리스트).

### 관문 3. 골드·강화 적용 상태에서의 연속 플레이
- **지금 기록(명세 6장):** 골드(2026-11-14), 네크로맨서 체력 강화, 1구역 되돌리기(2026-11-15), 소환수 능력치 강화(2026-11-17), 한 구역 내려가 골드 모으기(2026-11-18). 사장: 강화 전체를 모으는 반복이 길다는 것은 "의도한 것, 난이도는 잡으면 된다"(2026-11-19). 갑주·소총수 강화는 봇 수치에 거의 드러나지 않아 "폰으로 판단한다"고 적혀 있다.
- **넘었다고 볼 조건:**
  - 사장이 강화를 사며 여러 판·여러 구역을 이어서 하고, 막히는 구역에서 강화나 내려가기로 다시 나아갈 수 있다고 판정한다.
  - 앱을 닫았다 열어도 골드·강화·진행이 남는다(저장 `chimera-lab-save-v1`).
- **판정 방법:** 사장 폰 플레이. `test.cjs`는 강화·저장 규칙의 회귀를 보고, `node test.cjs --gold` 등 봇 수치는 참고로만 적는다.

### 관문 4. 사운드(소리) 확인
- **지금 기록:** 지시서 3.4: "소리: 사용자 폰이 진동 모드라 한 번도 확인받지 못했다." 소리는 `src/render.js`의 Web Audio로 코드에서 만든다(README, 명세 4.2). 명세 6장(2026-11-22)에 평타 소리가 셋 다 똑같이 들린다는 지적과 그에 따른 수정 기록이 있으나, **효과음 전체를 소리 켠 폰으로 확인했다는 기록은 없다.** 그래서 미확인으로 둔다.
- **넘었다고 볼 조건:** 사장이 소리를 켠 폰으로 흡수·익음(80%)·익은/덜 익은 폭발·초소 붕괴·돌격조 예고·평타 소리를 듣고, 거슬리지 않고 구별된다고 판정한다. 진동 모드에서도 게임이 그대로 되는지 본다.
- **판정 방법:** 사장 폰 플레이만. 자동 검증(`test.cjs`, `smoke.cjs`)은 소리를 듣지 못한다.

### 관문 5. 에셋·글꼴·서드파티 권리/라이선스 정리
- **이미 기록된 것(CREDITS.md 확인 현황):**

  - 원화·보관본 `art/**/*.png` 12/12: 소유자 직접 제작(OpenAI API 유료 요금제), 상업적 이용 가능.
  - 서드파티 `src/vendor/three/` 5/5 파일: 모두 MIT(three.js — Copyright © 2010-2024 three.js authors, meshoptimizer — Copyright (C) 2016-2022 Arseny Kapoulkine), 저작권·허가 고지 유지 조건.
  - 저장소 전체는 LICENSE에 따라 All Rights Reserved, `src/vendor/three/`만 예외.
- **아직 기록되지 않은 것(문서와 코드를 읽어 확인한 사실):**
  - **글꼴:** `src/page.html`이 Google Fonts에서 "Gowun Batang", "Gowun Dodum"을 불러 쓴다. CREDITS.md에는 글꼴 항목이 없다. 글꼴의 라이선스와 상업 이용 조건은 이 저장소 문서에 기록돼 있지 않으므로, 원 배포처의 라이선스를 직접 읽고 CREDITS.md에 더해야 한다(앱으로 묶어 배포하면 글꼴 파일을 함께 넣을지도 정한다).
  - **README 표기:** README 구조 표에 `src/render3d.js`가 "Three.js, CDN"으로 적혀 있으나, 지금 `build.cjs`의 importmap은 `three`를 `./src/vendor/three/three.module.min.js`로 풀고 부속도 로컬 벤더 파일을 부른다. 출시 전 README 표기를 실제와 맞출지 사장이 정한다(이 문서 작성 범위에서는 고치지 않았다).
- **넘었다고 볼 조건:**
  - 출시 결과물에 들어가는 모든 파일과 외부 리소스(글꼴 포함)가 CREDITS.md에 한 줄씩 있고, 확인 현황표 숫자가 맞는다.
  - 배포물(웹 페이지 또는 앱 안 "정보/라이선스" 화면 등)에 MIT 저작권·허가 고지가 들어간다. `src/vendor/three/LICENSE`는 지우거나 고치지 않는다.
  - CREDITS.md 권고대로 Tripo API·OpenAI API 결제 영수증과 생성일 기준 이용 약관(결과물 권리·상업 이용 조항)이 **저장소 밖에** 보관돼 있다. 저장소는 공개이므로 영수증 원본·결제 정보·API 키는 커밋하지 않는다.
- **판정 방법:** 사장이 문서를 확인한다. 자동 검증으로는 권리의 옳고 그름을 판단하지 못한다. 필요하면 외부 전문가 검토 여부도 사장이 정한다(`ask_first`, 비용 발생 가능).

### 관문 6. 배포 형태(웹 / 앱스토어) 선택
- **지금 기록:** README의 해 보기 주소는 GitHub Pages(https://guardi1017-web.github.io/chimera-lab/)이고, 지시서 3.2는 "push 한 번으로 폰에서 확인하는 속도를 지킨다"고 적는다. 상용 배포 형태에 대한 결정 기록은 없다.
- **고를 수 있는 후보(사장 결정 대상, 우열을 정하지 않음):**
  - 웹 배포 유지(지금 방식). 유료화 방식은 별도로 정한다.
  - 웹 게임 포털 등록.
  - 안드로이드 앱 스토어 등록. **`ask_first`**: 개발자 등록비가 든다.
  - iOS 앱 스토어 등록. **`ask_first`**: 연간 개발자 프로그램 비용이 든다.
  - 앱으로 감싸는 방식(웹을 앱 껍데기에 넣음)은 관문 2·4를 그 형태에서 다시 확인해야 한다.
- **비용·외부 등록 항목(모두 `ask_first`):** 스토어 개발자 등록비, 유료 도메인·호스팅, 결제·광고 연동, 사업자·세금 관련 등록, 외부 법률 검토. 금액과 조건은 실행 시점에 각 서비스의 공식 안내로 확인하고, 사장 승인 뒤에만 진행한다.
- **넘었다고 볼 조건:** 사장이 배포 형태를 고르고, 그 형태의 등록 조건·비용·심사 요구를 확인했으며, 고른 형태에서 관문 2·4를 다시 확인할 계획이 있다.
- **판정 방법:** 사장 결정.

## 4. 헌장 metrics 첫 지표 후보

비어 있는 헌장 metrics를 채울 첫 지표로 아래를 제안한다.

**지표: 통과한 관문 수 / 전체 관문 수** (초안 기준 현재 0 / 6)

- **산정 기준**
  - 분모: 사장이 "맞다" 또는 "바꿔라"(바꾼 뒤)로 확정한 관문 수. "빼라"로 표시한 관문은 분모에서 뺀다. 확정 전에는 초안의 6개를 쓴다.
  - 분자: 1장 표의 "넘었다고 볼 조건"을 채웠다고 **정해진 판정 주체가** 확인한 관문 수. 재미·화면·렌더링·소리가 걸린 관문(1~4)은 사장 폰 확인이 있어야만 센다. 봇 수치, `test.cjs`·`smoke.cjs` 통과만으로는 세지 않는다.
  - "부분" 상태는 분자에 넣지 않는다(0.5로 세지 않는다).
  - 통과한 관문도 그 관문에 해당하는 큰 변경(예: 3D 판 렌더링 변경, 배포 형태 변경, 새 에셋·글꼴 추가)이 생기면 다시 미확인으로 돌리고 분자에서 뺀다.
  - 기록할 때는 날짜, 관문 번호, 판정 주체, 근거(사장의 말 또는 확인한 문서)를 함께 남긴다.
- **활용 기준**
  - 진행 보고에 "통과 N / 전체 M"을 한 줄로 적고, 남은 관문 번호를 붙인다.
  - 이 지표는 출시 준비도만 나타낸다. 게임의 재미나 규모를 재는 지표가 아니며, 게임 내용에 상한을 두는 데 쓰지 않는다.
  - N = M이 되어도 출시 결정은 사장이 따로 한다.
